# 有界执行、记录与复核

## 1. 开始前的研究约定

从用户要求和已有文件填充，不把模板当作逐条问卷：

```text
任务范围：仅方案 / 审计已有结果 / 执行逆向实验。
目标与对象：比较哪些实验？固定哪个参考系统？想解释或改善什么？
指标：主指标、方向、逐样本定义、聚合单位及权重、辅助指标。
权限：可改位置；主模型训练、辅助探针、校准或门控拟合是否允许。
数据：发现/选择/复核用途，分组规则，标签权限，历史访问记录。
参数共享：全局 / 每数据集 / 每群体 / 可部署输入自适应；不能偷换。
成功：相对哪个基线？最小增益？需覆盖哪些群体/数据集？目标机制数量？
证据要求：探索性达标、独立复核或稳健性结论分别如何判定。
预算：时间、候选评估次数、算力、存储及复核/报告预留。
停止：预算耗尽、目标达成且必要检查完成、无效方向或不可恢复依赖。
产物：日志、配置、逐样本结果、复核记录和报告的实际保存位置。
```

未指定的成本低且可逆选择可采用合理默认并记录。关键条件无法确定时先做材料盘点、协议核验等独立工作，集中询问缺失项。没有真实保留数据时，可采用适当的分组嵌套验证或明确标为探索分析，不把已查看数据重新命名为盲测。

## 2. 可复现运行

记录足以重放的模型/代码/配置指纹、样本 ID 与顺序、预处理或支持集、推理状态、随机性及精度设置。重点是实际依赖，不机械哈希整个项目。

缓存中间特征前验证：下游是否依赖当前批次、历史窗口、运行统计、样本组合或支持数据？单个 query 张量可能不足以重放原协议。恒等重放失败时先定位缺失状态，不能把加速缓存的结果直接当原模型结果。

用少量样本验证原模型与干预路径，再测实际吞吐与资源。只有资源切换或数值差异会影响结论时才要求跨设备验证；不硬性要求 CPU/GPU 双跑。记录抽查范围，不能用局部等价宣称全量等价。调度参数和模型状态参数分开，增大并行数不得悄悄改变归一化或上下文长度。

## 3. 搜索与停止

按假设族组织候选；先验证恒等与有效扰动，再做小规模粗筛与有限邻域细化。搜索前写明范围、追加规则、选择标准和上限，保留失败、数值不合法及被淘汰的候选。

开发阶段可以依新证据调整计划，但要记录修改时间、理由和已查看数据；新机制作为新的开发迭代，不能混入原冻结清单。为复核与报告预留预算。若用户要求找到若干方法，数量是目标而非保证，不能靠改名、重复参数或放宽标准凑数。

记录总尝试数和选择过程；小样本上大规模选优可能产生偶然收益。按适当的独立统计单位给出不确定性，说明共享训练数据、重叠窗口和单训练种子的限制。需要显著性结论时考虑多重比较，不能通过挑一个有利检验替代既定主指标。

## 4. 冻结、复核与指标口径

复核前保存不可歧义的冻结清单：候选公式和参数、组合与顺序、开发排名、样本协议、代码/配置指纹、主指标计算、成功规则、数值一致性检查及复核范围。复核程序读取冻结清单；先验证清单，再运行评估。

保留数据揭示后不得按其结果重排、调参或更改验收标准。确需再研究时，把已暴露数据列为开发证据并建立新的复核安排；原来的失败和暴露记录仍保留。无标签的实现修复也应记录，核对是否改变算法并必要时作废受影响结果，不能仅因名为“修复”而豁免。

主指标按原始计数/未舍入值计算，区分百分点与相对百分比。报告每个独立单位的基线、改后结果、改对数、新错数、样本量及汇总方式。被试等权平均与所有样本合并准确率可以方向不同；不能用一种口径代替另一种，也不能根据四舍五入后的显示值判定是否改善。

把“满足用户设定的正增益门槛”和“统计稳定、机制特异、跨条件泛化”分开。轻微正值可以按约定达标，同时置信区间跨零、对照未胜出或仅单个种子都要准确报告。对照赢过目标时，不能仍声称确认了特异机制。

## 5. 持续维护的 Markdown 日志

执行多步实验时，在输出目录创建 `EXPERIMENT_LOG.md`，顶部状态可更新，历史实验卡保留。大量分数保存在 CSV/JSON 等机器记录中，日志只写摘要与路径。以下模板按任务裁剪：

```markdown
# 实验逆向工作记录

## 当前状态（每次恢复先读）
- 最近更新、当前阶段、运行/完成/未完成状态：
- 目标、授权范围和不可修改项：
- 主指标与聚合单位、验收与证据标准：
- 开发/复核数据与历史暴露；冻结清单位置：
- 预算已用/剩余、实际运行任务与输出位置：
- 当前最可信结论及其证据范围：
- 已排除方向、未解决问题：
- 下一步具体动作、所需前置条件：

## 证据与复现索引
- 源实验、模型、配置、数据协议与指纹：
- 基线重放和恒等检查：
- 候选表、逐样本结果、报告与恢复入口：

## 实验卡 E001
- 时间、状态（planned/running/completed/failed/partial）：
- 目的与可反驳假设；为何选择此实验：
- 输入证据、开发/复核归属、标签使用方式：
- 算子/公式、位置、参数、对照、应保持量：
- 实际运行命令或入口、环境、随机性、配置指纹：
- 结果：主指标原始值与增益、纠错/新增错误、影响群体：
- 操作有效性、数值检查、对照与副作用：
- 产物路径、完整性、耗时与资源：
- 解释：支持什么、不支持什么、否证或替代解释：
- 决策及下一步；任何计划变更及理由：

## 数据暴露与冻结事件
- 时间、读取了什么、用途、当时已冻结哪些内容：

## 最终交付
- 通过/未通过/未完成的候选与原因：
- 证据分级、结构建议、仍待验证的预测：
```

恢复时核对状态与文件：部分输出不是完成结果；匹配模型、数据、配置指纹才可复用；依赖状态无法恢复时从可重放边界重算。停止或清理仅针对本任务已确认归属的进程和临时文件。完成标记应在结果完整写入并校验后产生。

## 6. 最终报告与下一阶段

先回答目标完成多少，再列证据最强的变换或组合。每项包含：数学表达、部署所需输入、插入位置、收益与受益范围、对照、代价、机制解释与替代解释。附失败方向和完整搜索索引。

架构建议保留可追溯链条，例如：“局部对比在固定模型上优于匹配扰动，因此提出有界局部对比支路；尚需从头训练与等预算消融验证”。不得用“相关性高”“能量大”“可视化分得开”直接跳到“更有利的结构”。

## 7. 可复制的调用提示词

方括号为由用户填写的内容，已有信息可省略。

```text
使用 $reverse-engineer-experiments。
已有实验/消融及结果位置：[路径与简要差异]。
希望以 [参考模型或系统] 为基础，寻找 [更好的特征变换/融合/组件组合]。
主指标与成功标准：[指标、统计单位、最小收益或其他约束]。
可修改范围：[位置]；训练/校准权限：[具体范围]。
数据与已知暴露情况：[开发、复核和历史查看情况]。
本次范围：[先讨论并出计划 / 按已有授权执行]，预算：[时间/算力/次数]。
输出目录：[路径]。
请从现有材料提出可反驳假设，通过干预和对照逐步筛选；需要组合时
验证其相对最强单项的增益。维护 EXPERIMENT_LOG.md，记录每步目的、
结果与否证；最终区分实测改善、可能机制和待训练验证的结构建议。
```

本 skill 也适用于只提供预测分数的集成、检索/排序模块组合等任务：沿用相同证据流程，替换为相应的统计单位、干预对象和指标，跳过不适用的隐藏特征分析。不要为套用流程引入与任务无关的张量、频域操作或神经网络训练。
